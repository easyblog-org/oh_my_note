同样的模型，为什么别人输出精准，你却得到一堆废话？问题很可能出在提示词上。

作为开发者，我们早已习惯与机器“对话”——用代码发出指令，得到确定的结果。但和AI大模型交流时，这种确定性消失了。**模糊的提问，往往带来模糊甚至错误的答案**。于是，一门新的“手艺”应运而生：**提示词工程（Prompt Engineering）**。

简单说，提示词工程就是学习如何更清晰、更高效地向AI描述任务。它无关编程，更像一门“沟通的艺术”。本文将从最基础的Token概念讲起，带你系统掌握提示词的设计、优化与成本控制技巧。

## 一、基础概念：Token是什么？为什么它那么重要？
### 1.1 Token——大模型的计算单元
大模型并不直接理解“汉字”或“英文单词”，而是将文本拆解成更小的单元——**Token**。一个Token可能是一个完整的词、一个单词的一部分，甚至是一个标点符号。

不同模型对Token的切分方式略有不同，以OpenAI为例：

+ **英文**：1个Token ≈ 4个字符，或约0.75个单词。
+ **中文**：1个汉字通常编码为1~2个Token。
+ **空格、标点、表情符号**：都会占用Token。

**为什么要关心Token？**

+ **成本**：主流大模型API按输入+输出的Token总量计费。
+ **速度**：Token越多，模型推理耗时越长。
+ **限制**：每个模型都有最大上下文长度（例如4096或8192 Token），超出部分会被截断。

### 1.2 如何计算Token?
首先，不同大模型对Token的划分规则略有不同，比如根据OpenA的文档:

+ 英文文本：一个token大约相当于4个字符或约0.75个英文单词
+ 中文文本：一个汉字通常会被编码为1-2个token
+ 空格和标点也会计入token数量
+ 特殊符号和表情符号可能需要多个token来表示

简单估算一下，100个英文单词约等于75-150个Token，而1100个中文字符约等于100-200个Token。

实际应用中，更推荐使用工具来估计Prompt的Token数量，比如:

+ [OpenAl Tokenizer](https://platform.openai.com/tokenizer)：适用于OpenAl模型的官方Token计算器
+ 非官方的Token计算器

### 1.3 Token成本计算
估算成本有个公式：总成本 = (输入Token数 × 输入单价) + (输出Token数 × 输出单价)

不同大模型的计费都不太一样，因此要认真阅读官方文档的话+费标准，比如比如deepseek系大模型：

### 1.4 Token 成本优化技巧
前面说了，系统提示词、用户提示词和AI大模型输出的内容都是是消耗成本的，所以优化Token消耗，就是帮自己省钱。下面这四招是我实际用过并且效果明显的

#### 第一斧：精简系统提示词
很多人在写系统提示词时，喜欢给AI加一大堆人设修饰词，比如“非常专业”“经验丰富”“10年教学经验”……这些词对模型效果的影响微乎其微，但每一个都是实打实的Token。

❌ ** 反例**

> 你是一位非常专业、经验丰富、拥有10年教学经验的Python导师，你擅长用通俗易懂的方式向初学者解释复杂的编程概念，并且总是耐心细致地回答问题。
>

这一小段大概占了 **40~50个Token**。实际上真正有用的只有“你是Python导师”。

✅ ** 正例**

> 你是Python导师。
>

效果几乎一样，Token却从40+降到了 **5个**。省下80%以上。

**原则**：**只保留定义角色和核心约束的必要词**，所有修饰性的形容词、副词都可以删掉。如果非要加风格，用一个词就够了，比如“简洁”“幽默”“耐心”。

---

#### 第二斧：定期压缩对话历史 
在长对话场景（比如客服机器人、连续多轮的技术支持）中，每轮对话都会把之前的历史一起发给模型。如果聊了30轮，前面29轮的对话内容会反复被计入Token消耗。正确的做法是：

> 每进行5~10轮对话后，你对AI说：
>
> “请总结我们到目前为止的对话要点，用200字以内概括。接下来的对话将基于这个总结继续。”
>
> 然后把AI生成的总结作为后续对话的“历史上下文”。原本15000 Token的对话，压缩到200 Token左右，成本降低98%，而且模型依然能记住关键信息。
>

**原则**：**定期做“摘要压缩”**，把细碎的对话变成高密度的要点。尤其适合长会话场景。

---

#### 第三斧：使用RAG代替直接粘贴大文档
对于需要处理大量参考文档的场景,不要直接将整个文档作为Prompt,而是使用向量数据库和检索技术(RAG)获取相关段落

❌ ** 反例（暴力粘贴）**

> 你上传了一份50页的产品手册（约30000 Token），然后问：“这个产品的充电接口是什么类型的？”  
模型要读完30000 Token才能找到答案。你花了全部的钱，只用到其中100 Token的信息。
>

✅ ** 正例（RAG检索后再提问）**

> 先用向量数据库或检索工具（比如LangChain的RetrievalQA）把文档切分成小段并建立索引。当用户问“充电接口类型”时，系统先从索引中找出最相关的2-3个段落（几百Token），再将这几段和问题一起发给模型。  
你需要支付的Token数从30000降到不到1000，成本降低 **90%以上**，而且回答更精准（因为避免了无关内容的干扰）。
>

**原则**：让AI只读它真正需要读的那几页，而不是整本书。RAG（检索增强生成）是每个AI应用开发者都应该掌握的基本功。

---

#### 第四斧：结构化替代自然语言
同样的信息，用大段文字描述和用列表/表格表达，Token数量能差出好几倍。而且结构化的内容模型解析得更准确。

❌ ** 反例（散文式）**

> 请问如何制作披萨？首先需要准备面团材料，包括面粉、酵母、水、盐和橄榄油。然后根据个人口味选择酱料，可以是番茄酱或者白酱。接着准备奶酪，最常用的是马苏里拉奶酪。最后准备各种配料，比如意大利香肠、蘑菇、青椒等等。把这些材料组合起来之后放入烤箱烤制即可。
>

这段文字大概 **150~200 Token**，信息密度低，读起来也累。

✅ ** 正例（结构化）**

> 披萨制作材料：
>
> - 面团：面粉、酵母、水、盐、橄榄油
>
> - 酱料：番茄酱/白酱
>
> - 奶酪：马苏里拉
>
> - 配料：意大利香肠、蘑菇、青椒等
>
> 制作步骤：组合材料 → 烤箱烤制
>

同样的信息，只用了 **30~40 Token**，节省 **75%**，而且一目了然。

**原则**：**能用列表的不用段落，能用表格的不用列表**。不仅省Token，模型也更容易遵循你的格式要求。

## 二、提示词的分类
### 2.1 按角色分类（OpenAI API风格）
+ **系统提示词（System Prompt）**：设定AI的身份、行为准则和输出风格。如：“你是一名Java技术顾问，回答要简洁，优先给出代码示例。”
+ **用户提示词（User Prompt）**：用户发送的具体问题或指令。
+ **助手提示词（Assistant Prompt）**：模型的回答（可被用于多轮对话的示例）。

### 2.2 按功能分类（更适合实战）
| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 指令型 | 直接告诉AI做什么 | “将以下英文翻译成中文：...” |
| 对话型 | 以问答方式交互 | “什么是依赖注入？” |
| 创意型 | 生成故事、诗歌等 | “写一首关于春天的七言绝句。” |
| 角色扮演 | 让AI扮演特定角色 | “你现在是苏格拉底，请用提问的方式引导我思考。” |
| 少样本学习 | 提供几个示例，让AI模仿格式 | 给出2个“输入-输出”对，然后让AI处理新输入 |


### 2.3 按复杂度分类
+ **简单提示词**：单一问题或指令。
+ **复合提示词**：包含多个相关步骤。例如“总结文章要点，然后分析作者立场。”
+ **链式提示词**：前一步的输出作为后一步的输入。常用于复杂问题拆解。
+ **模板提示词**：带有变量的可复用结构（如“为[角色]写一份[主题]的周报”）。

## 三、提示词优化
前面也提到了，设计Prompt是一门艺术，高质量的Prompt可以显著提升AI输出的质量，设计高质量的提示词是一门需要刻意练习的技能。下面我将常见技巧分为**基础篇**和**进阶篇**，并配合具体案例。

### 3.1 基础技巧
#### 技巧1：明确任务和角色
```latex
系统: 你是一位经验丰富的Python教师,擅长向初学者解释级编程概念
用户: 请解释Python中的列表推导式,包括基本语法和2-3个实用示例
```

#### 技巧2：提供示例和输出格式
```plain
请为智能手表设计营销计划，按以下格式输出：
目标受众：...
内容主题：...
平台策略：[平台]-[内容类型]-[发布频率]
```

#### 技巧3：使用结构化格式引导思维
用表格、列表替代长段描述。例如，分析公司优劣势时：

```latex
分析以下公司的优势和劣势:
公司:Tesla

请使用表格格式回答,包含以下列:
-优势(最少3项)
-每项优势的简要分析
-劣势(最少3项)
-每项劣势的简要分析
-应对建议
```

#### 技巧4：明确输出约束（长度、风格、受众）
```latex
撰写一篇关于气候变化的科普文章,要求:
- 使用通俗易懂的语言,适合高中生阅读
- 包含5个小标题,每个标题下2-3段文字
- 总字数控制在800字左右

结尾提供3个可行的个人行动建议
```

### 3.2 进阶技巧
#### 1. 思维链（Chain-of-Thought, CoT）
引导模型展示推理过程，显著提高复杂逻辑题的准确率。

```plain
问题：一个商店卖T恤，每件15元。买5件以上打8折。小明买7件，需要付多少钱？

请一步步思考：
1.首先计算7件T恤的原价
2.确定是否符合折扣条件
3.如果符合,计算折扣后的价格
4.得出最终支付金额
```

#### 2. 少样本学习（Few-shot Learning）
给2~3个“输入-输出”例子，让AI理解模式。

```plain
情感分析示例：
输入：“服务太差了，等了一小时。” → 输出：负面
输入：“屏幕清晰，电池耐用。” → 输出：正面

现在分析：“这本书内容还行，就是价格有点贵。”
```

#### 3. 分步骤引导（Step-by-step）
将复杂任务拆解为可管理的步骤，确保AI不遗漏关键环节。

```plain
请设计一个智能家居系统方案，按以下步骤输出：

步骤1：分析用户需求（安全、节能、便利）
步骤2：列出核心设备（传感器、网关、执行器）
步骤3：绘制数据流（用ASCII示意）
步骤4：评估技术难点（隐私、兼容性）
```

#### 4. 自我评估与修正
让AI检查自己的答案并改进。

```plain
请计算：从一副扑克牌中随机抽两张，至少一张红桃的概率。
1. 先给出解答。
2. 检查推理过程有无逻辑漏洞。
3. 验证概率公式是否正确。
4. 如果发现错误，提供修正版。
```

#### 5. 多视角分析
要求AI从不同角色出发分析问题，获得更全面的见解。

```plain
分析“城市应禁止私家车进入市中心”：
- 环保专家视角：支持理由...反对理由...
- 经济学家视角：...
- 商户视角：...
- 通勤居民视角：...
```

#### 6. 知识检索与应用
让AI明确引用信息来源，增强可靠性。

```plain
请解释光合作用的过程。对于涉及数据或研究结论的陈述，请注明来源和发布机构。
```

## 四、提示词调试与优化
### 4.1 迭代优化法
好的提示词往往不是一蹴而就的。通过连续改进，逐步逼近理想结果。

| 版本 | 提示词 | 效果 |
| --- | --- | --- |
| v1 | “谈谈人工智能的影响” | 回答过于宽泛 |
| v2 | “分析AI对医疗行业的三大积极影响和两大风险” | 有了框架，但缺乏案例 |
| v3 | “详细说明AI在医学影像诊断中的应用：列出2-3个商业化系统及其准确率，以及实施挑战” | 得到具体、可用的答案 |


### 4.2 边界测试
尝试一些极端或困难的问题，摸清模型的能力上限和薄弱点。例如让模型证明复杂的几何定理，如果它失败，分析原因（是提示词不够清晰，还是模型本身知识不足？）。

### 4.3 提示词模板化
为重复性任务创建模板，保证输出的稳定性和一致性。

```plain
【专家角色】:{领域}专家
【任务描述】:{任务详细说明}
【所需内容】:
-{要点1}
-{要点2}
-{要点3}
【输出格式】:{格式要求}
【语言风格】:{风格要求}
【限制条件】:{字数、时间或其他限制}

例如:
【专家角色】:营养学专家
【任务描述】:为一位想减重的上班族设计一周健康饮食计十划
【所需内容】:
-七天的三餐安排
-每餐的大致卡路里
-准备建议和购物清单
【输出格式】:按日分段,每餐列出具体食物
【语言风格】:专业但友好
【限制条件】:考虑准备时间短,预算有限
```

### 4.4 错误分析与针对性修正
当AI生成的代码或答案有错误时，明确指出错误类型并要求重试。

```plain
发现之前请你生成的Xxx代码存在以下问题:
1.没有正确处理API不存在的情况
2.数据处理逻辑中存在边界条件错误
3.代码注释不够详细

请重新生成代码,特别注意:
1.添加完整的异常处理
2.测试并确保所有边界条件
3.为每个主要函数和复杂逻辑添加详细注释
4.遵循xxx编码规范
```

## 五、总结：把AI当作聪明的实习生
前面提到了这么多提示词优化技巧，但总结出来就一句话：**任务越复杂，就越要给提示词补充更多细节**。

我们不妨把AI看作一个知识渊博但缺乏主动性的**实习生**：你交代得越模糊，它越容易自由发挥（甚至胡说八道）；你给出清晰的背景、示例、步骤和格式，它就能交出高质量的答卷。

提示词工程没有绝对的标准答案，它更像一门需要反复练习的对话艺术。强烈推荐阅读Github上的经典小册 [**《How-To-Ask-Questions-The-Smart-Way》**](https://github.com/ryanhanwu/How-To-Ask-Questions-The-Smart-Way/blob/main/README-zh_CN.md) —— 要学会提问！

最后送你一个万能公式，适用于大部分任务：

> [角色] + [任务] + [示例/输入] + [步骤] + [输出格式] + [约束条件]
>

掌握它，你的AI使用体验将提升一个量级。现在，去试试优化你的第一条提示词吧！
